# Требования к производительности будущей веб-версии TaskTracker

## 1. Загрузка данных

Приложение не должно загружать большой объём данных, который пользователь в данный момент не использует.

## 2. Большие списки

Для большого количества задач (более 100) необходимо использовать постраничную загрузку (pagination) или постепенную подгрузку (lazy loading). Не выводить сразу более 50–100 строк.

## 3. Клиентский JavaScript

Следует избегать длительных вычислений в основном потоке, которые блокируют интерфейс. Тяжёлые операции выносить в Web Workers или на сервер.

## 4. Медиа и вложения

Тяжёлые вложения и изображения загружать только по запросу (при открытии карточки задачи). Использовать сжатие и кэширование.

## 5. Работа на слабых компьютерах

Интерфейс должен оставаться работоспособным на устройствах с 4 ГБ RAM и слабым процессором. Не использовать тяжёлые анимации без необходимости.

## 6. Проверка производительности

Перед релизом проверять время загрузки страницы (не более 2 секунд), потребление RAM (не более 500 МБ на 10 вкладок), скорость выполнения JavaScript (не более 100 мс на сложный расчёт).

## 7. Автообновление

Не проверять сервер каждую секунду. Использовать интервал не чаще 30 секунд или WebSocket-уведомления.
